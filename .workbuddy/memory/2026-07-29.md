## 修复 Ark API 400 Invalid request body（error-state tool part rawInput 双重序列化）

- **根因**：会话 `nqPx65q3g6Z7I8abR2j46` 中 `save_wiki` 工具调用出错后，AI SDK 在 UIMessage part 中存储 `rawInput`（字符串）而非 `input`（对象）。`convertToModelMessages` 回退使用 `rawInput`，OpenAI-compatible provider 对其执行 `JSON.stringify(string)` 产生双重序列化的 `arguments`，Ark API（deepseek-v4-flash）拒绝并返回 400。
- **验证**：从 DB 提取 4 条 UIMessage（2 条含大量工具调用的 assistant 消息），转换为 90 条 API messages 后逐步二分定位到第 79 条（error-state tool result）。修复 `arguments` 双重序列化后请求返回 200。
- **修复**：新增 `packages/core/src/modules/agent/sanitize-messages.ts`，导出 `sanitizeToolErrorInputs` 函数，在 UIMessage 到达 `convertToModelMessages` 之前将 error-state tool part 的 `rawInput`（字符串）解析为对象。在 `chat/route.ts` 和 `composition/inbound/agent-handler.ts` 两处入口调用。
- **测试**：8 项单元测试全部通过；Core typecheck 通过。
- **系统性加固**：新增 `fixDoubleSerializedArguments` 作为 provider 层 `transformRequestBody` 安全网，在 `createModelProvider` 中始终启用。无论消息从哪条路径到达 provider（DB 加载、当前 run 内新产生、inbound handler），最后一刻都会检测并修复双重序列化的 `tool_calls.arguments`。新增 6 项测试覆盖该函数，共 14 项测试全部通过，Core typecheck 通过。
