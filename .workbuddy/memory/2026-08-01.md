## Agent 持续学习的数据层思路

讨论确认：Wiki 适合保存语义化结论，Skill 保存可复用方法，MCP/连接器负责获取外部数据；若 Agent 要通过每日采集形成趋势、异常与归因，产品还需要一个由 Agent 管理的结构化事实/时间序列存储层。SQLite 适合作为本地优先 MVP，但应通过受控数据 API 提供，而不是把数据库文件或任意 SQL 直接暴露给 Agent；后续需要考虑数据集隔离、schema 演进、来源与时间元数据、保留策略、配额、导出和云同步。

补充决策：为什么用受控 API 而非裸 SQL——(1) 安全底线：LLM 写 SQL 的 DROP/ALTER/笛卡尔 JOIN 风险无法靠"别犯错"规避，API 让破坏性操作在结构上不存在；(2) 元数据强制注入（collected_at/source）是跨日分析的数据质量基础；(3) 接口稳定，存储从 SQLite 演进到云端时 Agent/Skill 零改动；(4) 配额/审计/隔离依赖 API 作为治理入口。复杂分析可开放"只读 SQL"档（仅 SELECT+聚合，禁写操作，强制 LIMIT），即"API 是边界，SQL 是边界内的可选项"。
