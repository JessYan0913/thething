# 2026-08-04 工作日志

## 上下文详情数据错误排查

**问题**：输入框附近「上下文占用详情」面板数据一直不对（总计虚高、明细栏全为 0）。

**根因**：存在两套并行的 token 计算体系，前端展示混用了它们：

- **体系 A（增量估算，正确）**：`core/src/modules/compaction/incremental-estimation.ts` + `token-counter.ts`，在 `pipeline.ts` prepareStep 调用，算出 messages/instructions/tools/outputReserve 明细 + total（当前窗口真实占用）。但**只用于压缩闸门，不推送前端、不写库**（pipeline.ts:213 注释明确）。
- **体系 B（TokenBudgetTracker，累计）**：`core/src/modules/session/token-budget.ts`，在 `app/api/chat/route.ts` onStepEnd 用 `getSummary()` 推送 `data-context-usage` + 调 `updateContextBudget` 写库。total = 每步 inputTokens 累加 + output 累加，是**会话累计值**，不是当前窗口占用。

**三个具体断裂点**：
1. `route.ts:487-496` 推送的 `data-context-usage` 完全不含 messagesTokens/instructionsTokens/toolsTokens/outputReserve → 流式期间明细栏拿不到数据，`?? 0` 显示 0。
2. `route.ts:503-509` 调 `updateContextBudget` 写库时不传明细字段 → conversation-store 的 context_messages 等列始终 NULL（`conversation-store.ts:86` 用 `?? null`）。而 `create.ts:392-406` 定义的闭包虽支持明细，但 prepareStep 不调它，只有 onStepEnd 调且不传明细。
3. totalTokens/usagePercentage 用体系 B 累计值冒充「当前窗口占用」→ 百分比虚高、长对话可能超 100%、明细加起来 ≠ 总计。

**数据链路**：前端 `Chat.tsx:1013` effectiveContextBudget = 流式 ?? 持久化兜底 ?? prop（ChatPage.tsx:18-35 从 conversation 对象读 context* 字段）。

**结论**：「会话累计」区块（输入/输出/缓存）口径自洽是对的；「总计/百分比/明细」三块数据来源错误。修复方向：让 onStepEnd 同时推送 prepareStep 的估算结果（带明细的当前窗口占用）作为总计/百分比/明细的来源。
