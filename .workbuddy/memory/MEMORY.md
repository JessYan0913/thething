# Project Memory

## UI / 产品约定

- 聊天输入框的模型选择器应显示真实模型名，而不是只显示 Default/Fast/Smart 别名；触发器需设置合理最大宽度并截断，完整名称可通过 tooltip 查看。
- 后续模型配置计划支持同时添加多个供应商，届时输入框需要承担跨供应商的模型选择能力；当前暂不实施这部分扩展。
- 对话路线面板应以路线关系为主、消息内容为辅：默认只展示轨道、分叉节点、路线终点、路线名称和当前位置，不在每个节点右侧常驻消息摘要；桌面端悬浮快速预览，点击后固定详情并提供切换操作，兼顾触屏设备。

## Wiki / Skill 沉淀约定

- 当前任务目标决定主要交付，沉淀不能替代、偏离或拖延当前任务；任务完成后允许 Agent 做一次受控的自主学习反思。
- Wiki 用于概念性知识，如定义、原理、架构、术语关系和稳定机制；仅在内容稳定、新颖、可信且具有通用性时自主写入或更新。
- Skill 用于可复用的执行能力，如触发条件、步骤、工具调用、异常处理和验证标准；用户明确要求创建或封装 Skill 时，必须产出可被加载器识别的 SKILL.md，Wiki 不能替代。
- 搜索外部资料、阅读 GitHub 仓库或完成一次操作本身，不构成自动沉淀理由；临时信息、操作日志、一次性配置和重复内容默认不沉淀。
- Wiki / Skill 边界和安全修复必须基于通用语义与不变量设计，不得把某次回归话术中的具体名词、页面名或操作场景固化为产品规则；具体关键词只能作为辅助信号，最终应校验“当前任务目标—内容类型—交付容器”是否一致。
