# Project Memory

## UI / 产品约定

- 聊天输入框的模型选择器应显示真实模型名，而不是只显示 Default/Fast/Smart 别名；触发器需设置合理最大宽度并截断，完整名称可通过 tooltip 查看。
- 后续模型配置计划支持同时添加多个供应商，届时输入框需要承担跨供应商的模型选择能力；当前暂不实施这部分扩展。
- 对话路线面板应以路线关系为主、消息内容为辅：默认只展示轨道、分叉节点、路线终点、路线名称和当前位置，不在每个节点右侧常驻消息摘要；桌面端悬浮快速预览，点击后固定详情并提供切换操作，兼顾触屏设备。

## Wiki / Skill 沉淀约定

- 当前任务目标决定主要交付，沉淀不能替代、偏离或拖延当前任务；任务完成后允许 Agent 做一次受控的自主学习反思。
- Wiki 是由 Agent 持续维护的复利知识工件，可包含来源摘要、实体、概念、事件、步骤、比较、项目知识和演化中的综合分析；不要求预先归入固定知识类型，也不必等到完全稳定或结构完美才记录。
- Skill 用于可复用的执行能力；用户明确要求创建或封装 Skill 时，主要交付仍应是可被加载器识别的 SKILL.md，Wiki 不能替代，但 Wiki 与 Skill 之间不做工具层硬隔离。
- Wiki 应通过 Ingest、Query 回写和 Lint 持续修订、合并、交叉引用及处理冲突；页面结构、分类和工作流允许随领域与使用过程共同演化。
- 不再推进以严格分类、内容纯度拒绝、Skill 写入硬授权和多交付工具证据验收为核心的治理方案；仅保留防止真实数据损坏的不变量约束。
